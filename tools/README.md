# Porting tools

These exist to compare this service against the Node implementations in
[hebcal-web](https://github.com/hebcal/hebcal-web) and `@hebcal/*`. They live
here rather than there because they are artifacts of the port: hebcal-web has
no use for them. (The tools that compared PDF renderings were removed when the
JavaScript PDF renderer was retired.)

They are not part of the build. Nothing in `*.go` imports them, and the service
does not need Node or Python to run.

## Why they need hebcal-web

The `.mjs` tools import `@hebcal/core` and `dayjs` out of hebcal-web's
`node_modules`, because the point is to measure the reference implementation
rather than a second copy of it that might drift. They expect a hebcal-web
checkout with its dependencies installed:

```sh
git clone https://github.com/hebcal/hebcal-web ../hebcal-web
cd ../hebcal-web && npm install
```

They look for it at `../hebcal-web`; set `HEBCAL_WEB` if it lives elsewhere.
Node resolves bare specifiers relative to the importing file, so a tool in this
directory cannot simply `import '@hebcal/core'` even when run from hebcal-web —
`hebcalweb.mjs` builds absolute file URLs to work around that, and everything
else goes through it.

## dump-locales.mjs

Regenerates `internal/model/calendarnames.go`.

```sh
node tools/dump-locales.mjs --go > internal/model/calendarnames.go
gofmt -w internal/model/calendarnames.go
```

hebcal-web takes its month and weekday names from the dayjs locales that
`src/dayjs-locales.js` imports. Generating from the same source is what keeps a
German or Portuguese calendar reading identically in both implementations,
rather than a hand-typed table that drifts. Re-run it if hebcal-web adds a
locale to `localeMap` in `src/lang.js`.

## dump-urls.mjs

Dumps every event and its canonical URL from `@hebcal/core`, for diffing against
the same range generated by hebcal-go.

```sh
node tools/dump-urls.mjs diaspora > /tmp/js-d.tsv
node tools/dump-urls.mjs il       > /tmp/js-i.tsv
```

Running this over 1990–2089 on both schedules found three URL bugs that a single
year did not: Yom Kippur Katan has no page at all, a common year's single Adar
must not be numbered `adar-i`, and Erev Pesach and Erev Sukkot were missing the
`IL_ONLY`/`CHUL_ONLY` flags that decide whether a link carries `?i=on`. Those
fixes are in hebcal-go v0.19.0. The Go half of that comparison was a throwaway
`cmd/` program in hebcal-go; if the comparison is worth repeating, it is worth
rewriting there rather than keeping a copy here.

## ics-compare.sh, ics-sweep.sh, ics-v4.mjs, readings-stub.mjs

Compare the holiday `.ics` feeds with hebcal-web's. Run hebcal-web's download
app (`cd ../hebcal-web && npm install && npm run dev:download`, port 8081), this
service on :8082 with `-readings-socket` pointing at the stub, and the stub:

```sh
node tools/readings-stub.mjs /tmp/readings.sock &
./hebcal-api -port 8082 -zips-db ../hebcal-web/zips.sqlite3 \
  -geonames-db ../hebcal-web/geonames.sqlite3 -readings-socket /tmp/readings.sock
tools/ics-sweep.sh tools/ics-cases.txt
```

`readings-stub.mjs` answers readings-svc's `/torahMemo` with hebcal-web's own
`makeTorahMemoText()`, so the descriptions can be compared without the sidecar.
`ics-compare.sh <url>` diffs one URL (`TIMES=1` to see the minute-level time
differences it hides; Rosh Hashana's year, which differs on purpose, is always
hidden). `ics-sweep.sh <file>` runs every query string in a file (one per line;
`ics-cases.txt` is the set the port was measured with) in the classic, `/v2/h/`
and `/v4/` forms -- `ics-v4.mjs` builds the last with hebcal-web's own encoder
-- and prints the ones that differ. `CGI_ONLY=1` skips the other two forms.

## ics-goldens.sh, dump-kl-dates.mjs

`ics-goldens.sh` regenerates `internal/service/ical/testdata` -- the golden feeds
hebcal-web renders for `cases.tsv`, and the readings the tests answer in place of
readings-svc -- and `dump-kl-dates.mjs` writes `internal/service/ical/kldates.go`,
how `Intl` formats the dates in a Kiddush Levana description in each locale
(Go has no CLDR). Re-run the second if hebcal-web's locale list grows.
